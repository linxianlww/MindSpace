# MindSpace (NekoBox) UI 全量重构方案 — miuix 优先架构

## 一、现状诊断

代码可编译（analyze 0 错误、31 测试全过），问题是三个架构性根因：

1. **设计系统层污染**：`lib/ui/design_system/app_design_system.dart` barrel 同时导出 `flutter/material.dart` 和 `flutter_miuix`，导致 Material 组件到处渗漏；29 个 `App*` 包装文件中约 2/3 只是对 miuix 组件 1:1 改名。
2. **脚手架误用**：`AppView` 是 Flutter 原生 `Scaffold` + 硬编码背景（`#F7F7F7`/`#121212`）。之前放弃 `MiuixScaffold` 的理由不成立——已核实其源码：content 本来就是满屏布局、通过 `content: (padding)=>…` 回传避让内边距，这正是折叠大标题（内容滚动到顶栏之下）的正确模式，与 CustomScrollView 天然兼容。
3. **死代码堆积**：安卓小组件原生层已删但 Dart 残留 4 个孤儿文件 + app.dart 死监听；`UiStyle` 切换机制废弃；`md3e_*` 旧包装与 `App*` 新包装重复；数据模型 `memo.dart` 反向依赖 UI barrel。

已确认的既定方向：**保持 push 导航、标准 HyperOS 风格（不用 OS4 玻璃）、全量重构**。

## 二、Phase 1 — 主题管线与设计系统层重构

### 1.1 主题（单一事实来源）
- 保留 `MiuixThemeController(isDark, colorSchemeMode, keyColor)` 为唯一配色来源（已支持动态取色/品牌橙 seed/深浅色）。
- `app.dart` 桥接修正：`_miuixToColorScheme` 中 `surfaceVariant` → `surfaceContainerHighest`（消除 analyzer 弃用告警），补 `surfaceContainer` 层级映射；删除 app.dart 中小组件死代码（`_listenWidgetClicks`/`_handleInitialWidgetDeepLink`/`_routeFromWidgetUri`/`_openCreate`/`_toggleTodo` 及相关 import）。
- `core/theme/app_theme.dart` 瘦身为纯 Material 兼容桥（仅供 flutter_quill、chewie、pdfrx 等第三方内部渲染用），删除已无渲染对象的 MD3 组件主题。
- 删除废弃机制：`core/constants/ui_style.dart`、`core/theme/style_provider.dart`、`AppSettings.uiStyle`、`SettingsNotifier.setUiStyle`、对应 pref key；`Md3eTokens` 品牌色并入 `tokens.dart` 后删除 `md3e_tokens.dart`。
- `data/models/memo.dart` 的 UI barrel import 改为 `dart:ui`（仅取 `Color`），消除层级违规。

### 1.2 barrel 收紧
```dart
export 'package:flutter/widgets.dart';      // Icon/IconData 已验证在 widgets 库
export 'package:flutter_miuix/miuix.dart';

// 不再导出 material.dart；需要 Icons/Colors 的页面写
// import 'package:flutter/material.dart' show Icons, Colors;
```

### 1.3 组件层处置（29 个 App* 文件）
**删除 1:1 包装，页面直用 miuix**（改动调用点）：`app_button`→`MiuixButton`/`MiuixTextButton`、`app_switch`→`MiuixSwitchPreference`/`MiuixSwitch`、`app_checkbox`→`MiuixCheckbox`、`app_radio`→`MiuixRadioButton`、`app_slider`→`MiuixSlider`、`app_range_slider`→`MiuixRangeSlider`（记录 `(double,double)`）、`app_text_field`→`MiuixTextField`、`app_icon_button`→`MiuixIconButton`、`app_progress`→`MiuixLinear/Circular/InfiniteProgressIndicator`、`app_divider`→`MiuixHorizontal/VerticalDivider`、`app_tooltip`→`MiuixTooltipBox`、`app_refresh`→`MiuixPullToRefresh`、`app_tab_bar`→`MiuixTabRow`、`app_list_tile`→`MiuixBasicComponent`、`app_card`→`MiuixSurface(cornerRadius:)`、`app_navigation_bar`、`app_drawer`（导航决策后无用）。

**重写为 miuix 正确用法**：
- `app_scaffold.dart`：`AppScaffold` 包装 `MiuixScaffold`（containerColor 取 `MiuixTheme` background，内部创建 `MiuixSnackbarHostState` + `MiuixSnackbarHost`/`MiuixPopupHost` 并经 InheritedWidget 暴露供 `AppSnackbar.show(context, …)` 查找）；content 走 builder 模式。`AppHeader` 保留为 `MiuixSmallTopAppBar` 适配器；新增首页折叠大标题用法 `MiuixTopAppBar(scrollBehavior: MiuixExitUntilCollapsedScrollBehavior, blurred: true)`。
- `app_dialog.dart`/`app_sheet.dart`：命令式 helper 内部渲染声明式 `MiuixOverlayDialog`/`MiuixOverlayBottomSheet`（show 标志驱动，进出场用 MiuixPopup 默认弹簧）。
- `app_snackbar.dart`：从 scope 取 `MiuixSnackbarHostState.showSnackbar(message, actionLabel:)`，删除 ScaffoldMessenger 后备路径。
- `floating_toolbar.dart`（core/widgets）：基于 `MiuixFloatingToolbar` 重写。

**保留的自定义价值组件**：`AppTokens`、MemoTile/FolderTile/MemoMasonry（瀑布流，视觉对齐 MiuixCard sink 反馈 + squircle）、`AppDataTable`（XLSX 查看）、`AppReorderableDragHandle`、state_views（迁入 design system，用 `MiuixInfiniteProgressIndicator`/`MiuixButton` 重做）、PIN 输入对话框（安全组件保留，token 对齐）。

**core/widgets 清理**：删除 `md3e_card.dart`、`md3e_switch.dart`（调用点迁到 MiuixCard/MiuixSwitch），`state_views.dart` 迁移。

## 风险与对策
- **MiuixScaffold 布局**：已在源码层面确认满屏模式可行；首页作为首个落地页验证模式，若仍有边缘问题（键盘避让/estimate 一帧沉降），备选方案是保留满屏布局但用 `MediaQuery.removePadding` 微调，不再回退到原生 Scaffold。
- **第三方包内部依赖 Material**（quill/chewie/pdfrx）：Material 桥主题保留，只保证我们自己的代码不再直接用 Material widget。
- **改动面大**：4 个批次每批结束都保持可编译、测试通过，随时可停。
